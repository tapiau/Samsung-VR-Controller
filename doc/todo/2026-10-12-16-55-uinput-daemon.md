# uinput daemon: Gear VR Controller as system input
**Created:** 2026-10-12 16:55

## Goal
A user-level daemon that keeps a BLE connection to the controller and turns its packets
into Linux input events through `/dev/uinput`, so it works under any session (the desktop
here is Wayland, where X11 tools like xdotool won't work).

## Facts this builds on
- Protocol: `doc/protocol.md` (start with `0800` + `0100`, keepalive `0400` every 1 s,
  60-byte packets, ~43/s).
- `/dev/uinput` is `root:root 0600` → needs a udev rule (one-time, sudo, done by the user).
- `python-evdev` installs into `.venv` without extra system packages.

## Design
```
controller ──BLE──> ble.py ──packets──> protocol.py ──State──> mapper.py ──events──> uinput device
                    (connect, start,    (decode into           (touch → pointer,
                     keepalive,          dataclass: buttons,    buttons → keys,
                     reconnect)          touch, imu samples)    edge detection)
```
- `vrcontroller/protocol.py`: pure decode (moved out of `tools/dump.py`, which then imports it).
- `vrcontroller/mapper.py`: pure logic, no I/O; takes the decoded state, returns
  input events. Holds touch tracking (deltas, smoothing, acceleration) and button edge
  detection. This is where the tests focus.
- `vrcontroller/daemon.py`: BLE loop (bleak, BlueZ path connect) + one virtual device made with
  `evdev.UInput` (REL_X/REL_Y/REL_WHEEL/REL_HWHEEL, BTN_LEFT/RIGHT/MIDDLE, the mapped keys).
- Reconnect: the controller sleeps after inactivity; on disconnect, retry with backoff and wake
  up again when it reconnects (home button wakes it).
- Run: `.venv/bin/python -m vrcontroller`; later a `systemd --user` unit for autostart.

## Mapping (decided 2026-10-12)
Defaults live in code (`vrcontroller/config.py`); an optional TOML file overrides any of them.

Defaults:
| Input | Action |
|---|---|
| Finger slides on touchpad | move pointer (relative, like a laptop touchpad; delta from touch start) |
| Trigger | left click (hold = drag) |
| Touchpad click | right click |
| Back held + slide | scroll (vertical + horizontal) |
| Back tap (no slide) | `KEY_BACK` |
| Home | `KEY_LEFTMETA` (Super) |
| Vol+ / Vol− | `KEY_VOLUMEUP` / `KEY_VOLUMEDOWN` |
| Gyro "air mouse" | phase 2, not in v1 |

Scroll modifier rule: whichever button is the scroll modifier fires its own action only on a
*tap* (released without sliding); held + slide scrolls instead.

### Config file
Path: `$XDG_CONFIG_HOME/vrcontroller/config.toml` (default `~/.config/...`), or `--config PATH`.
Parsed with stdlib `tomllib`; every key is optional and merged over the defaults; unknown keys
or event names → exit with a clear error naming the key.
```toml
[pointer]
speed = 1.0            # pointer units per touchpad unit
acceleration = 1.0     # 1.0 = linear

[scroll]
speed = 1.0
natural = false        # true = content follows the finger
modifier = "back"      # trigger | click | back | home | vol_up | vol_down

[buttons]              # evdev names; "KEY_LEFTCTRL+KEY_C" for combos, "none" to disable
trigger  = "BTN_LEFT"
click    = "BTN_RIGHT"
back     = "KEY_BACK"
home     = "KEY_LEFTMETA"
vol_up   = "KEY_VOLUMEUP"
vol_down = "KEY_VOLUMEDOWN"
```
`config.example.toml` in the repo documents all keys. The user's own file will set
`scroll.modifier = "click"` (touchpad click'n'slide = scroll, click tap = right click).

## Success criteria
- `pytest` passes.
- `libinput debug-events` shows the virtual device; each button produces the mapped event once
  per press (press + release, no repeats, no stuck keys after disconnect).
- Pointer follows finger with no jump when a new touch starts; scroll works with the modifier held, and the modifier tap still sends its own action.
- Changing the config file (e.g. `scroll.modifier`) changes behaviour after a daemon restart.
- Turning the controller off or letting it sleep → daemon logs disconnect, keeps running, and resumes
  within a few seconds after the home button wakes the controller.
- CPU use of the daemon stays low (< 5 % of one core) at ~43 packets/s.

## Progress notes (2026-10-12)
- udev rule alone was not enough: the `uinput` module wasn't loaded, so `/dev/uinput` was only
  a static placeholder and `udevadm trigger` said "No such device". `modprobe uinput` +
  `/etc/modules-load.d/uinput.conf` fixed it (README updated).
- Controller lost its pairing (probably a long home press): it advertised but dropped every
  connection during service discovery. `bluetoothctl remove` + pair again fixed it.
- Daemon now scans before connecting when BlueZ says the controller isn't connected; connecting by
  object path alone never succeeds for a controller that just woke up.
- Added a local status page (`http://127.0.0.1:8765/`, SSE) on user request.
- Pointer was jumpy: packets arrive in bursts (~3 per BLE connection event, ~50 ms apart) and
  fast swipes/lift-off produce 54–109 unit jumps. Added EMA smoothing (`pointer.smoothing`,
  default 0.5) and dropping steps > 80 units. User's speed set to 0.6; user confirmed it feels good.
- Still to verify: scrolling (click'n'slide), all buttons through the system, reconnect after
  the controller sleeps.
